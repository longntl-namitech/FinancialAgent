# restructure-readme - Spec

Source of decisions: [grill.md](grill.md) (8 questions, all decided).

## Intent

The repo is flat: five modules at the root and generic top-level package names (`model`, `memory`, `utils`, `graph`), with `graph/graph.py` importing its own package. The README is a stub (one PNG, an install line, a file tree with "other_files..."). Goal: a single-package layout, a README a newcomer can read in one screen, and diagrams that can be regenerated.

## Goals, non-goals, anti-goals

**Goals**
- One package `financial_agent/`; no behaviour change.
- README redesigned per the writing-readme skill, in English, every claim checked in the repo.
- Hand-drawn SVG diagrams generated by a script in `docs/diagrams/`.

**Non-goals**
- Fixing the small issues found (duplicate `upload_dir` in config, unused `update_memory` import, possibly unused `convert_to_message` / `get_session_id`), adding tests, adding a LICENSE, adding `pyproject.toml`, pinning `requirements.txt`. These go in the PR description only.
- Renaming the runtime string `"file_controler"`.

**Anti-goals**
- A change in the supervisor prompt text, the node ids, or the SSE output.
- A README sentence that is not checkable in the repo.

## Approaches

One sensible way: `git mv` each file (keeps history), rewrite imports with a mechanical find-and-replace, then check by importing and booting the app. Alternatives not taken: copy-and-delete (loses `git log --follow`), and a compatibility shim at the old paths (the user wants the old layout gone).

## Constraints and my calls

- **My call, differs slightly from the grill summary:** `app.py` sits at the package root (`financial_agent/app.py`), not in `api/`, so the decided run command `uvicorn financial_agent.app:app` holds. `api/` holds the routes and auth.
- **My call:** `python app.py` becomes `python -m financial_agent.app`.
- Paths in `Config` (`temp/uploads`, `temp/message_logs`) and `.env` are relative to the working directory, so everything runs from the repo root, as today. `.gitignore` is not touched.
- `demo/streamlit_demo.py` imports `logger` and `config`; those become `financial_agent.core.*`, so run it from the repo root. If it references `examples/` by path, update that path (to be checked while implementing).
- Runtime strings (`"file_controler"`, agent and node names, prompts) are not edited.

## README structure

Per the writing-readme skill, in this order; sections that do not apply are left out (no results section: the repo measures nothing).

1. Header: "Financial agent", the existing tagline idea (multi-agent assistant for analyzing financial documents), badges only for verifiable facts (FastAPI, LangGraph, OpenAI via `llm_model_name`, no license or Python-version badge), anchor links.
2. Intro and an "at a glance" table (counts taken from the code: agent stages, tools, endpoints).
3. Architecture: `pipeline.svg`, `layout.svg`, link to the old `architecture.png` and `SystemDesign.pdf`; stack table in `<details>`.
4. Catalogue: one table of the agents (memory, planning, supervisor, analyzer, file controller, response) with role and tools, in pipeline order.
5. Quickstart: three numbered commands (install, set `.env`, run), rest in `<details>` (demo UI, calling the API).
6. Project layout, tests (none yet), licenses (the repo has no license file; stated as such).

## Diagrams

Generated by `docs/diagrams/make_diagrams.py` (copied from the skill's `sketch.py`, with its font and `OFL.txt`); the script is re-runnable and leaves unchanged SVGs byte-identical.
- `pipeline.svg`: user → API (`/api/v1/chat/ainvoke`, API-key auth) → memory (reads/writes the local store) → planning → supervisor ⇄ analyzer / file controller ⇄ their tools → response → SSE stream to the user.
- `layout.svg`: the package tree above.

Fills: lilac inputs, yellow parts that call the LLM, green plain code, blue stores. Flow edges are checked against `agents/graph.py` and `routers/chat.py`; the PNG's "Tools" and "Repeat" loops are verified against the sub-graph code before being drawn.

## Verification (no tests exist)

1. `grep -rn` for any leftover old import path (`^from (config|logger|utils|model|memory|graph|routers|dependencies)\b`) returns nothing outside valid internal ones.
2. With dummy env vars (`OPENAI_API_KEY`, `FASTAPI_KEYS`, `AUTH_ENCRYPTION_KEY`), `python -c "import financial_agent.app"` succeeds and `GET /api/v1/health` returns 200 through `fastapi.testclient`.
3. Render each SVG with headless Chrome and read the PNG for overlaps and cut-off labels.
4. Every README command and path exists (grep or run).
